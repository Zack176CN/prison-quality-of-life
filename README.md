# 生活与质量更新 1.6.3

[English](README.en.md)

这是《监狱建筑师》的 Windows 补丁管理器。它把砍树、换门、课程进度、员工士气和出货调度等功能做成独立选项。在 `Prison QoL.exe` 中勾选并应用，之后照常从 Steam 启动游戏。

适用 **Windows Steam x64 构建 10630057**。支持原版、Tyr 1.5.0 的默认修复配置，以及该配置加上 Tyr 士气衰减的版本。管理器按游戏程序的 SHA-256 识别版本，遇到未识别的程序会拒绝写入。

## 安装与应用

1. 在 Steam 创意工坊订阅。第一次启动游戏，在「附加功能 → 模组」确认 `Prison Quality of Life` 已出现，保存并完全退出游戏。已经有补丁管理器的玩家可以直接从第 3 步开始。 [生活与质量更新创意工坊页面](https://steamcommunity.com/sharedfiles/filedetails/?id=3843268843)
2. 按 **Win + E**，把下方目录粘贴到文件资源管理器地址栏，回车后双击 `Prison QoL.exe`。如果目录不存在，在 `%LOCALAPPDATA%\Introversion\Prison Architect\mods` 下搜索该文件，在条目根目录的 `manifest.txt` 中确认名称为 `Prison Quality of Life`。程序旁的 `README - Prison QoL.txt` 也有双语指南。

   ```text
   %LOCALAPPDATA%\Introversion\Prison Architect\mods\-451698453\data\prisonqol
   ```

3. 在管理器核对游戏路径及版本。点「自动检测」可重新扫描 Steam 库。要手动选择，在 Steam 库右键《监狱建筑师》，点「管理 → 浏览本地文件」，回到管理器点「选择目录…」，选择包含 `Prison Architect64.exe` 的文件夹。也可以把文件夹或游戏程序拖进管理器窗口。
4. 勾选需要的补丁，点击「应用」。状态显示「已应用，可从 Steam 正常启动」后，关闭管理器并从 Steam 进入游戏。首次使用会选中「出货调度」「出货调度台」和容量的「首选方案」。管理器会读回之前应用过的设置。
5. 从 1.0.0–1.6.2 升级时，保留游戏目录内的 `Prison QoL Backup`。打开新版管理器，核对识别到的旧选项并点击「应用」。

## 施工与经营补丁

在游戏退出时勾选对应选项并应用。回游戏后按下表操作。

| 管理器选项 | 游戏内操作和效果 |
| --- | --- |
| **砍树后不留树桩** | 照常指派工人砍树。完工时仍有木材可用，树的位置不会留下新树桩。存档里已有的树桩可正常拆掉。 |
| **自动替换已安装的旧门** | 选另一种单格或双格门，单击旧门实际占用的任一格。用墙换门时，可单击一格，也可拖过整段门洞。新门或墙完工后，工人可搬走打包的旧门。双格门也只回收一件。 |
| **建门和墙前自动清理树木** | 在有树木或树桩的位置放单格门、双格门，或直接拖墙。工人会先清理施工范围内的树木，再建造。可以与「砍树后不留树桩」同时开启。 |
| **修复改造计划进度保存** | 应用后照常开设「三振出局计划」（Second Chances DLC）或「鲜花疗法」（Going Green DLC）。课程刷新名单时使用额定人数，学员可继续累积存档中已有的进度。 |
| **员工死亡士气惩罚逐渐消退** | 第一次出现尚未消退的惩罚后，每过 1,440 游戏分钟减轻 1 点。原版死亡统计、无事故计时及奖励照常。游戏世界重新加载时会重新计算衰减状态。 |

例如，要把双格门洞全部封起来，选墙壁工具拖过原门的两格。只建一格墙或只换成单格门时，另一格会留空。要用双格门替换单格门，新门占用的相邻格也必须可以施工。公路闸门等更宽的门仍按游戏原有流程建拆。

课程修复可以保留存档中已有的进度。已清空的进度与已记录的结业结果按存档读取。曾手动放入 `data/reform_programs_dlc.txt` 的玩家，可在游戏关闭时把该覆盖文件备份并移出 `data`，让游戏从原本的 `main.dat` 读取课程要求。

## 出货调度、均衡取货和货车容量

### 建调度台并发车

1. 保存并退出。打开管理器，勾选「出货调度」和「出货调度台」。如果希望轮流收垃圾和出口货物，也勾选同组的「均衡取货」。点击「应用」，从 Steam 启动游戏。
2. 在「物件」搜索「出货调度台」，也可在送货区、垃圾区或出货区的推荐物件里找到它。设备造价 **200**，占一格。可建在室内、室外或区域外的可施工格。
3. 选中已建成的调度台，点「召唤一辆货车」或「召唤两辆货车」。队列最多等待 **5 辆**，每次加派至少间隔 **5 个游戏分钟**。「货车上限」可设 **1–5 辆**，已进场的供给货车也计入上限。入口被占用时，请等车辆通过。
4. 想在货物积压时自动派车，点「自动调度」选择每 **15、30 或 60 个游戏分钟**检查，也可以选关闭。点「积压门槛」选择 **4、8 或 16 堆**，默认 8 堆。达到门槛时尝试加派一辆。
5. 菜单底部的「垃圾积压」「出货积压」统计道路停靠点服务的区域。刚载入时若显示「待统计」，让游戏时钟走一会儿。看「最近调度」能判断是请求入队、已发车、还在等发车间隔、入口占用、达到上限，还是暂未达到门槛。
6. 已应用「均衡取货」的玩家，可在调度台菜单里把它打开。垃圾和出货物品都在积压时，加派车交替专收垃圾或出口货物。只有一类积压时，车辆按平常规则取货。例如，两类货物都堆满时可以排两辆车，再查看它们分别取走了什么。

同一座监狱内的调度台共用一个队列和一组设置。读档后自动调度、均衡取货和下一辆加派车的车长会恢复默认。

### 选择 8、12 或 16 个货位

在管理器的「出货调度 → 供给货车容量」二选一。

| 方案 | 怎样设置 | 对哪些车生效 |
| --- | --- | --- |
| **首选方案** | 启用调度台并应用。进游戏后点击「车长」，在标准 8 格、中型 12 格和加长 16 格之间切换。选好再提交派车请求。 | 调度台此后加派的车辆，含手动与自动调度。普通送货车保持 8 格。读档后下一辆加派车从 8 格开始。 |
| **备选方案** | 退出游戏，在管理器选「游戏默认（原版 8 格）」「固定容量（12 格）」或「固定容量（16 格）」，点击「应用」。 | 所有供给货车都使用所选容量。车辆沿用原版车身，只绘制前 8 个货位。完整货量可在车辆提示里查看。 |

12 和 16 指货位数量。首选方案的车型仍是两列货位，标准、中型、加长车的道路占位长度分别为 8、10、12 格。想保留旧扩容模组给所有车辆增加货位的效果，选对应的固定容量即可。想让普通送货车保持原样，只把某次出货加派的车加长，就用首选方案。

切换方案前，在游戏中关闭自动调度，停止追加手动请求。等队列处理完、加派车驶离后保存并退出，再用管理器切换。要在同一个存档停用调度台，先拆除所有调度台并保存。

## 从旧物流模组迁移

1. 用「保存监狱」另存一份备份。还在使用旧调度台时，先关自动调度和均衡取货，停止手动派车，等额外货车离开地图。
2. 拆除旧调度台并保存用于迁移的存档。在「附加功能 → 模组」停用用过的旧 12 格、16 格和 `Outbound Logistics - Dispatch` 条目，完全退出游戏。
3. 在 `Prison QoL.exe` 应用新版选项，从 Steam 启动并载入迁移存档。原来的 `Start Balanced Logistics.cmd` 可以停用。若首次载入提示缺少模组，核对提示里列出的是否为刚停用的条目。
4. 需要派车时从「物件」重建调度台，重新选择自动调度、车辆上限、均衡取货和车长。确认存档运转正常后，可在创意工坊退订旧条目。

## Tyr、备份和恢复

- **Tyr 的士气选项已启用**。管理器会将同类选项置灰，防止重复应用。要改用本项目的版本，先退出游戏。如果已经应用过本项目，先点「恢复原文件」回到应用前的 Tyr 程序。再打开 Tyr 1.5.0，取消 **Staff death morale penalty fades** 并应用。最后回到本管理器勾选「员工死亡士气惩罚逐渐消退」及其他所需选项，点击「应用」。
- **备份在哪里**。首次应用会把原版或 Tyr 游戏程序保存到安装目录里的 `Prison QoL Backup`。后续应用使用校验过的备份生成所选组合。这个文件夹用于备份游戏程序，监狱存档仍通过游戏的「保存监狱」另存。
- **关闭部分补丁**。先完成或取消受影响的施工任务。要关闭调度台，先等加派车离场、拆除调度台并保存。完全退出游戏，在管理器取消勾选相应项并应用。取消「出货调度」总开关会停用整组功能。
- **恢复全部并退订**。按上一步处理仍在使用的补丁，完全退出游戏后在管理器点击「恢复原文件」。完成后即可退订。Steam 验证文件完整性或更新后，也可打开管理器用「复查当前目录」核对版本及已应用的选项。

## 从源码构建

使用 Windows x64、Python 3.10 或更新版本、PowerShell，以及附带 x64 `csc.exe` 的 .NET Framework 4.x。生成补丁目录时，需要准备两份来自自己游戏安装的可执行文件副本。第一份是受支持的 Windows Steam 原版，第二份是同一游戏构建的 Tyr 1.5.0 默认修复版，Tyr 的士气衰减开关可开可关。构建工具会校验这两个输入。

在仓库根目录打开 PowerShell，命令中的两个路径请换成自己的副本路径。

```powershell
$stockExe = 'C:\PA-build-inputs\stock\Prison Architect64.exe'
$tyrExe = 'C:\PA-build-inputs\tyr-1.5.0\Prison Architect64.exe'
python .\build_patch_catalog.py --steam $stockExe --tyr $tyrExe --output .\patches.json
if ($LASTEXITCODE -ne 0) { throw '补丁目录生成失败' }
& .\app\Build-App.ps1 -CatalogPath .\patches.json
```

编译得到仓库根目录下的 `Prison QoL.exe`。C# 管理器会把生成的补丁目录嵌入程序。仓库提供源码和构建脚本，游戏程序与补丁目录由上面的步骤在本机准备和生成。

| 位置 | 内容 |
| --- | --- |
| [`app/`](app/) | WinForms 管理器、Steam 目录检测、版本校验、应用和恢复。 |
| [`features/`](features/) | 施工、物流、课程与士气等原生补丁模块及其构建数据。 |
| [`build_patch_catalog.py`](build_patch_catalog.py) | 核对支持的游戏构建，生成管理器需要的补丁目录。 |
| [`patch_image.py`](patch_image.py) | 在内存中处理 Windows x64 游戏文件的构建工具。 |
